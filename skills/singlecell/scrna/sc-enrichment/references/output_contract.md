# Enrichment outputs

ORA/GSEA CLI writes `processed.h5ad`, `report.md`, `result.json`, the resolved
GMT library, and `reproducibility/{commands.sh,requirements.txt}`.

`tables/` holds `enrichment_results.csv`, `enrichment_significant.csv`,
`group_summary.csv`, `ranking_input.csv`, and `top_terms.csv`.
The results identify group, term, gene set, source, engine, method, score and
available p-values/overlap/leading-edge fields. The significant table uses
FDR 0.05; the group summary uses the requested FDR threshold.
Python GSEA may add `gsea_running_scores.csv`. `figure_data/` mirrors these
tables and writes `manifest.json`. No `tables/de_full.csv` or marker table is
created merely because such a table was consumed upstream.

Plots are conditional on usable terms: enrichment top-term, group-summary,
dotplot, network, ridge and GSEA running-score figures are generated by the
shared plotting helpers. `--r-enhanced` adds the applicable `r_enrichment_*`
and `r_gsea_*` figures when its R renderers succeed.

The clusterProfiler engine additionally writes `clusterprofiler_results.csv`,
`r_plot_metadata.json` when plots exist, `r_figures/`, and
`reproducibility/r_engine_inputs/`. The legacy GSEA database bridge uses
`r_work/{de_for_gsea_r,gsea_r_results}.csv`. GSVA instead writes
`tables/gsva_r_scores.csv`, `r_work_gsva/`, `figures/gsva_r_heatmap.png`, the
processed H5AD and its report/result/reproducibility files.

The API returns tables and Figures. Its R work directories are temporary;
private table attrs retain artifacts only for CLI compatibility. `run_info`
returns JSON diagnostics without embedding those files or full rankings.
