- **🤝 Step 6.12 of the framework rebuild: sub-agent delegation** — `omicsclaw/subagent/` ([plan 0046](docs/plans/0046-subagent-layer.md)) gives the agent a `task` tool: it hands a bounded sub-task to a specialised agent that runs with its own context and its own narrowed tool set, and gets back one self-contained conclusion instead of thirty turns of intermediate noise. A sub-agent is not a new abstraction — it is one more `AgentEngine` running one `exchange`, handed **no conversation at all**, which is also the whole of its context isolation: the parent's history does not reach it because no path exists that could carry it. Three properties were built to be structural rather than disciplined. **The child's tools are the parent's own already-gated objects**, filtered by name, so a sub-agent can never be wider than the deployment that started it — and they are re-registered with the parent registry's own resolved policies, because `GatedTool` reads the policy the *executing* registry publishes and a naive copy silently drops a deployment's `register(policy=)` tightening. **The delegation tool is removed from every child tool set**, unconditionally — that filter is the single narrowing point and the one real guard against recursion; `TaskTool` additionally refuses a definition that would still resolve the tool, which checks the definition rather than the registry the child actually received. **Approval needed no plumbing**: `contextvars` copy into each new Task, so a sub-agent's `bash` reaches the parent turn's real `ApprovalBroker` across two Task boundaries — predicted by plan 0027 §12.6 before either side existed, measured here. `task` holds the engine's timeout pause for the whole run, because `tool_timeout` is sized for one call and a delegation is many; what bounds a runaway one is `turn_timeout_s`. Tools reach the loop through a two-method `ToolExecutor` Protocol that step 4 will satisfy structurally, while dispatch policy — concurrency, per-tool timeout, result ordering — stays in the engine. Taking the name required evicting the live legacy loop to `omicsclaw/runtime/engine/`: it was not merely occupied but *unimportable*, since its `__init__.py` pulls the `openai` SDK at module scope. One declared schema amendment came with it (`StreamChunk.finish_reason`), so a stream cut off by the output ceiling is no longer indistinguishable from a model that finished. **635 passing tests**, no network, neither vendor SDK installed. Two independent read-only evaluations gated the step — correctness and harness9 feature parity — and both found real defects that were repaired as a separate task; they converged on the same two independently. Nothing is wired to it yet; the Tool Registry is step 4. See [plan 0027](docs/plans/0027-react-main-loop.md).

Nothing is wired to it yet; the Main Loop is step 3, and the pre-existing `omicsclaw/providers/` stays live and untouched until the closing migration. See [plan 0026](docs/plans/0026-provider-layer-simultaneous-interpreter.md).
- **🩸 Step 1 of the framework rebuild: one shared schema** — `omicsclaw/schema/` is the vendor-neutral contract every component will exchange: `Message` (carrying the ReAct Thought as `reasoning_content`), `ToolCall`, `ToolResult`, `ToolDefinition`, `Usage`, `StreamChunk`. Standard library only, importing nothing from `omicsclaw`, so it can be depended on from any boundary without creating a cycle — `import omicsclaw.schema` loads 5 modules in ~9 ms.
